Unlike modern operating system experiments that mount over convenience platforms (such as UEFI, GNU-EFI abstractions, or multi-gigabyte GCC toolchains running on desktop workstations), ROS enforces a strict **Zero-Abstraction Doctrine**. Every component—from the 16-bit Master Boot Record (MBR) bootstrap sequence to the Protected Mode Global Descriptor Table (GDT), hardware Interrupt Descriptor Table (IDT), Programmable Interrupt Controller (PIC) bus remapping, and memory-mapped VGA framebuffers—was engineered from architectural ground zero. The entire operating system was conceived, implemented, compiled, and debugged on an ARM-based mobile device running an isolated Linux userspace (Termux), proving that low-level hardware governance requires only strict algorithmic precision and systems engineering discipline. --- ## 🏛️ Architectural Taxonomy & Hardware Abstraction

--- ## 🔬 Deep-Dive Subsystem Specifications ### 1. The Stage-1 Bootstrap Vector & Real-to-Protected Engine * **Vector Entry (`0x7C00`):** Execution begins as legacy BIOS stages the 512-byte MBR payload at physical linear address `0x0000:0x7C00` in 16-bit Real Mode. * **Direct Disk DMA via BIOS Services:** The bootloader drives BIOS Interrupt `0x13` (`AH=0x02`, `AL=50`) to issue direct sector polling off the raw drive cylinder, loading 50 contiguous sectors (25,600 bytes) of binary kernel payload into high conventional memory at segment `0x1000`. * **Global Descriptor Table (GDT) Realignment:** Deconstructs Real Mode segment registers (`CS:IP`) into a linear 4GB Flat Memory Model across Ring 0 Supervisor privileges: * `0x00`: Null Descriptor (Mandatory Hardware Guard). * `0x08`: 32-bit Code Segment Descriptor (`Base=0x0`, `Limit=0xFFFFF`, `Access=0x9A`, `Flags=0xCF`). * `0x10`: 32-bit Data Segment Descriptor (`Base=0x0`, `Limit=0xFFFFF`, `Access=0x92`, `Flags=0xCF`). * **Protected Mode Elevation:** The bootloader loads the GDT register via `lgdt`, asserts the Protected Mode Enable (`PE`, Bit 0) flag in control register `CR0`, executes a pipeline-clearing Far Jump (`jmp 0x08:init_pm`), aligns segment registers (`DS`, `SS`, `ES`, `FS`, `GS`) to selector `0x10`, instantiates the stack at `0x90000`, and invokes the kernel entry point. ### 2. The Monolithic Freestanding Kernel * **Freestanding C Runtime:** Operates completely independent of libc or hosted runtime support. Built with `-ffreestanding -fno-pie -mno-red-zone`, ensuring no unexpected stack corruptions or dynamic symbol references take place. * **Direct Linear Video Framebuffer Control (`0x000B8000`):** Drives screen rendering via memory-mapped I/O (MMIO). The 80-column by 25-row matrix is mapped as an array of 2-byte word cells: $$\text{Memory Address} = \text{0xB8000} + 2 \times (\text{row} \times 80 + \text{column})$$ * *Low Byte:* Character ASCII Token. * *High Byte:* Hardware Attribute Byte (Bits 0–3: Foreground, Bits 4–6: Background, Bit 7: Blink Flag). * **Defensive Video Engine:** Integrates real-time cursor boundary tracking, dynamic horizontal string centering algorithms, backspace cell clearing, and an automated viewport reset trigger on line overflow ($> 2000$ cells) to prevent video buffer overruns. ### 3. Dual PIC Cascading & Asynchronous IDT Dispatch * **Interrupt Descriptor Table (IDT):** Houses 256 interrupt gates constructed in linear RAM, registered into the CPU via the `lidt` instruction. * **Dual Intel 8259 Programmable Interrupt Controller (PIC) Remapping:** Resolves hardware IRQ conflicts with x86 CPU Exception Traps ($0x00-0x1F$) by remapping the master and slave PIC base vectors to safely routed hardware gates ($0x20$ and $0x28$) via standard I/O initialization words: * `ICW1 (0x11)`: Edge-triggered mode, cascaded PIC setup. * `ICW2 (Master 0x20, Slave 0x28)`: Target vector base mappings. * `ICW3 (0x04, 0x02)`: Master-to-slave IRQ2 interconnection mapping. * `ICW4 (0x01)`: 8086/88 microprocessor architecture mode lock. * **Asynchronous PS/2 Input Driver (IRQ1 / Interrupt Gate 33):** The keyboard driver is built on a custom naked interrupt handler (`__attribute__((naked))`) that preserves register frames via `pushal`/`popal`, polls raw byte scan codes from data port `0x60`, maps make/break scan codes against a US QWERTY translation layout, buffers ASCII streams, and dispatches End-of-Interrupt (`EOI`) acknowledgment bytes (`0x20`) to the PIC command port `0x20`. ### 4. Direct Hardware Power Reset * **Intel 8042 Keyboard Controller Bus Injection:** Bypasses software halting loops (`hlt`) to enforce a true motherboard-level CPU reset. By asserting reset line state transitions via output control byte `0xFE` directly into hardware port `0x64`, the system pulses the CPU `INIT` line, forcing an instantaneous hardware reboot to the BIOS post vector. --- ## 🗺️ Engineering Roadmap & Future Milestones

[x] Phase 1 (Stabilized Core): Real-to-Protected Mode transition, GDT/IDT construction, PIC cascade remapping, PS/2 driver, dynamic VGA attribute engine, centered UI framework, and I/O port resets.

[ ] Phase 2 (Hardware Clocking): Programmable Interval Timer (Intel 8253/8254 PIT) integration to drive high-resolution preemptive ticks and real-time execution sleep timers.

[ ] Phase 3 (Physical Disk Management): Implement an ATA/IDE PIO Mode controller driver to read and write raw disk blocks directly from the kernel interface.
